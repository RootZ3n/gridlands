# Content ids and tags: grammar and validation rules

Decision record: [ADR-0020](ADR/0020-content-ids-and-tags.md). The M2
validator enforces every rule marked **[V]**. This document is the
specification the validator is tested against.

## 1. Entity ids

```
id        = kind "." segment "." segment *( "." segment )     ; 3 to 5 segments in total
kind      = one of the registered kinds (section 2)
segment   = lower 0*31( lower / digit / "_" )                  ; 1..32 chars
lower     = "a".."z"
digit     = "0".."9"
```

Rules:
- **[V] ID-1** Matches the grammar above: 3–5 dot-separated segments, each
  `^[a-z][a-z0-9_]{0,31}$`, with no `__` and no trailing `_`. Total length at
  most 96 characters.
- **[V] ID-2** The first segment is a registered **kind**, and it matches the
  entity's type: an item's id starts with `item.`.
- **[V] ID-3** Ids are unique across all of `Data/`.
- **[V] ID-4** **File path mirrors id**: entity `item.material.copper_wire` lives at
  `Data/item/material/copper_wire.json` (one entity per file). Cell-scoped kinds
  live under their cell (section 3).
- **[V] ID-5** Every reference to another entity is a full id, resolves to an
  existing entity, and has the kind the field expects (a recipe `output` must be
  an `item.*`).
- **ID-6 Stability.** An id is a save key and a cross-reference. During
  bootstrap, ids may be renamed freely. After the first persistent save-bearing
  build, a rename requires an entry in `Data/_aliases.json` (`old -> new`) plus
  a save migration. **[V]** Aliases must resolve, and must not chain or cycle.
- **ID-7** Names describe the thing, not its tuning: `copper_wire`, not
  `copper_wire_x3`.
- **[V] ID-8** Every entity file has `"schemaVersion": <int>` and `"id"`.

**[V] ID-9** A new kind is added only with a typed C++ definition (ADR-0021)
and an entry here. It's a code change, reviewed.

## 2b. Content rules beyond the grammar

- **[V] KN-1** A knowledge entry's `sources` must be backed by content: `Source.Salvage`
  needs a salvage whose `onSalvageUnlocks` grants it, and `Source.Discovery` needs an item whose
  `onAcquireUnlocks` grants it. That way NC-2 cannot be satisfied on paper only.

## 2a. Loader rules (C++, ADR-0021)

The engine's loader re-checks what it depends on: ID-1, ID-2, ID-3, ID-4,
ID-8 and ID-9, plus:
- **CXX-1**: a JSON key with no matching C++ field (closed schemas in C++ too);
- **CXX-2**: a value the typed definition cannot hold.

A file that fails is refused, never loaded partially.

## 3. Cell-scoped ids

A cell's **short name** is the last segment of its cell id
(`cell.home.origin` -> `origin`). Placements and anchors put that short name
second, and their files mirror their ids like every other entity:

```
Data/cell/home/origin.json                       cell.home.origin
Data/placement/origin/glitch_kitchen_wall.json   placement.origin.glitch_kitchen_wall
Data/anchor/origin.generated.json                anchor.origin.*  (one generated file per cell; never hand-edited)
```

- **[V] ID-10** The second segment of a `placement.*` or `anchor.*` id is an
  existing cell's short name. **[V]** Cell short names are unique.
- The anchor file is the one exception to one-entity-per-file. It is
  generated by the editor export (ADR-0018) and checked for sync.

## 4. Tags

Tags are Unreal Gameplay Tags used for **categories**, not entities.

```
tag       = namespace *( "." part )
namespace = registered namespace (section 5)
part      = upper *( alpha / digit )          ; PascalCase, 1..32 chars
```

- **[V] TAG-1** Grammar as above, at most 4 parts, at most 96 characters.
- **[V] TAG-2** The first part is a **registered namespace**.
- **[V] TAG-3** Every tag used in `Data/` is declared: in `Config/Tags/*.ini`
  (hand-written system vocabularies), or generated from data (e.g. each era
  definition declares its `Era.*` tag, and the generated tag file is checked for
  sync).
- **TAG-4** Tags never carry tuning or identity. "Which item" is an id;
  "what kind of thing" is a tag.

## 6. Eras (ADR-0020)

The ten established eras are **data**: `Data/era/memory/*.json`, each with an
id, display name and `Era.*` tag. They are not a C++ enum and not a tier.

| Era | id | tag |
|---|---|---|
| Ice Age | `era.memory.ice_age` | `Era.IceAge` |
| Ancient Library | `era.memory.ancient_library` | `Era.AncientLibrary` |
| Roman | `era.memory.roman` | `Era.Roman` |
| Medieval / Hedge Knight | `era.memory.medieval_hedge_knight` | `Era.MedievalHedgeKnight` |
| Feudal Japan | `era.memory.feudal_japan` | `Era.FeudalJapan` |
| Victorian | `era.memory.victorian` | `Era.Victorian` |
| 1800s Native American | `era.memory.native_american_1800s` | `Era.NativeAmerican1800s` |
| 1920s | `era.memory.twenties` | `Era.Twenties` |
| 1950s | `era.memory.fifties` | `Era.Fifties` |
| Modern Day | `era.memory.modern_day` | `Era.ModernDay` |

**[V] ERA-1** No gameplay-power field (damage, support strength, yield) may
be keyed on era. Power comes from materials.
